# Content Strategy

## Narrative Thesis

Felix turns manufacturing project chaos into measurable execution improvement.

The website should not read like a conventional developer portfolio. It should read like a manufacturing improvement evidence room: outcomes first, workflow map second, case studies third, and public sanitized tool evidence fourth.

Core message:

> I support manufacturing projects across planning, material readiness, trial production, PPAP, ramp-up, shipment, delivery, audit support, and corrective action. I use structured follow-up, Lean/Six Sigma thinking, PDCA cycles, and practical digital tools to reduce waiting, repeated manual checking, information searching, over-processing, coordination errors, rework, and scrap.

## Homepage Narrative

Recommended order:

1. Outcomes and positioning
2. Impact metrics
3. Full-cycle manufacturing project map
4. Featured case studies
5. Portfolio Lab as public evidence
6. Methodology
7. About
8. Resume/contact call to action
9. Confidentiality note

The homepage should start with what Felix improves, not with a biography.

## Audience Reading Path

### Manufacturing Professionals

They should quickly recognize:

- Risk review, DFMEA-related follow-up, process preparation, BOM/material readiness, trial production, takt simulation, PPAP, mass production, shipment, delivery, audit support, corrective action, and improvement reporting.
- Familiar waste categories: waiting, repeated checks, information searching, over-processing, coordination errors, rework, scrap, and trial-and-error waste.
- Practical project control methods: Gantt charts, milestone tracking, issue lists, cross-functional follow-up, regular reporting, and PDCA.

### Recruiters

They should quickly understand:

- The target role family: manufacturing project coordination, manufacturing systems, process improvement, supply chain operations, smart manufacturing, MES/WMS/ERP business analysis.
- Four high-signal impact metrics.
- The public portfolio evidence is safe, sanitized, and reviewable.
- Felix is not claiming to be a pure software engineer or pure AI researcher.
- How to contact or request a resume.

### Technical Readers

They should see:

- Data-driven content.
- Public demos and GitHub repositories.
- Local-first design, deterministic calculation, validation scripts, quality gates, and data safety boundaries.
- Agent or AI concepts only where they support reviewable workflows, source references, or verification.

## Case Study Hierarchy

### 1. Trial Production Takt Simulation and Changeover Improvement

Use this as the most visual case. It connects directly to trial production, bottleneck analysis, scrap reduction, and estimated changeover savings.

Primary metric:

- 3 days -> 1 day for trial analysis and adjustment cycle.
- Around 90 percent scrap reduction.
- Estimated RMB 20,000 per regular model changeover.

Primary evidence:

- Factory Takt Simulator.

### 2. Production Notice Workflow Standardization

Use this as the clearest workflow automation and standardization case.

Primary metric:

- 20-40 minutes -> under 1 minute.

Primary evidence:

- Structured Operations Notice Workbench.

### 3. Supply-Production-Delivery Operations Visibility

Use this to show department-level reporting and daily execution visibility.

Primary metric:

- Dashboard adopted in departmental workflow and reporting analysis.
- Qualitative reduction in waiting, repeated manual checks, information searching, over-processing, coordination errors, and rework.

Primary evidence:

- Factory Excel Ops Dashboard.

## Homepage Versus Detail Pages

Homepage should show:

- Short case summaries.
- Metrics.
- Before/after diagrams.
- Links to public evidence.
- Clear confidentiality statement.

Case detail pages should show:

- Business problem.
- Felix's role.
- Methods.
- Actions.
- Outcome metrics.
- Before/after workflow.
- Related public project.
- Confidentiality boundary.

## Impact Metrics

Use four primary metric cards:

| Metric | Label | Wording guard |
| --- | --- | --- |
| 20-40 min -> <1 min | Production notice preparation | Use "around" for the baseline range. |
| 3 days -> 1 day | Trial takt analysis and adjustment | Present as cycle shortened, not universal guarantee. |
| Around 90 percent reduction | Trial machining and debugging scrap | Tie to trial machining/debugging context. |
| Around RMB 20,000/changeover | Regular model changeover saving | Always use "estimated". |

## Portfolio Lab Strategy

The Portfolio Lab should support the manufacturing story. It should not become the main page.

Recommended groups:

- Main evidence:
  - Factory Takt Simulator
  - Structured Operations Notice Workbench
  - Factory Excel Ops Dashboard
- System concept:
  - Operations Intelligence Platform
- Data and learning support:
  - Factory Data Pocket Lab
  - Six Sigma Study App
- Experimental verification:
  - HulunGuard

Do not show private repositories as public evidence. BOM Knowledge Base can be reserved for future public release or mentioned as a private/sanitization-pending direction only if needed.

## Confidentiality Framing

Use this text on the homepage, case studies, and Portfolio Lab:

> This portfolio uses sanitized or synthetic data to demonstrate selected improvement outcomes and tool concepts based on real manufacturing workflow patterns. No customer names, private BOMs, supplier records, internal system exports, production routes, machine parameters, or confidential factory files are disclosed.

Make confidentiality part of professional maturity. It should read as a strength, not as a defensive footnote.

## Tone Guide

Prefer:

- reduced
- shortened
- standardized
- coordinated
- tracked
- improved visibility
- enabled review
- public sanitized showcase
- synthetic-data demo
- estimated savings

Avoid:

- AI genius wording
- pure machine learning positioning
- claims of enterprise deployment where evidence is a demo
- broad keyword lists without proof
- exaggerated transformation language
